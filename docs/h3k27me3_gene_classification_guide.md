# Guide: Classification of genes by H3K27me3 domain width at the TSS

This guide documents the procedure used in this repository to classify genes into broad, narrow, and negative groups based on the width of the H3K27me3 domain overlapping the transcription start site (TSS). The logic follows the R scripts in [bin/D0_H3K27me3_genes_classification.R](../bin/D0_H3K27me3_genes_classification.R) and [bin/D4_H3K27me3_genes_classification.R](../bin/D4_H3K27me3_genes_classification.R).

## 1. Goal of the analysis

The goal is to assign each gene to one of three categories based on the H3K27me3 signal present at its promoter:

- Broad: the TSS overlaps a H3K27me3 domain wider than 6000 bp
- Narrow: the TSS overlaps a H3K27me3 domain of 6000 bp or less, but greater than 0 bp
- Negative: no detectable H3K27me3 domain overlaps the TSS

This classification provides a simple way to compare genes that lie in broad repressive chromatin domains versus those that are only weakly marked or not marked at the promoter.

## 2. Inputs required

A typical analysis requires:

- H3K27me3 peak calls or peak regions from the relevant ChIP-seq experiment
- a gene annotation file with TSS coordinates
- a consistent genome assembly, typically mm10 in this project
- optionally, a list of differentially expressed genes or other gene sets for downstream comparison

The script workflow assumes that a TSS-linked H3K27me3 table is available as an input file or generated in a preceding step.

## 3. Prepare H3K27me3 domains

The H3K27me3 peaks used in this workflow were derived from the study by Sánchez-Gaya and Rada-Iglesias, POSTRE: a tool to predict the pathological effects of human structural variants. Nucleic Acids Res 51, e54 (2023). In the repository workflow, these peaks are treated as the input signal for defining H3K27me3 domains around gene TSSs.

The procedure used is based on defining domain-like intervals from the H3K27me3 signal and then measuring the width of the region overlapping each gene TSS. In practice, this means:

1. Start from the H3K27me3 peak set derived from the study above.
2. Define the relevant H3K27me3 interval associated with each gene promoter.
3. Measure the width of the interval overlapping the TSS.
4. Use the resulting interval width to assign the gene to broad, narrow, or negative classes.

The repository’s downstream scripts use this interval width directly as the key feature for gene classification.

## 4. Assign each gene to a TSS-associated domain

For each gene, identify the TSS coordinate from the annotation and test whether it overlaps an H3K27me3 domain.

The logic is:

- if the TSS overlaps a domain and the domain width is greater than 6000 bp, classify the gene as broad
- if the TSS overlaps a domain and the domain width is less than or equal to 6000 bp, classify the gene as narrow
- if no domain overlaps the TSS, classify the gene as negative

This is the same threshold used in the repository scripts:

```r
broad_thresholds <- 6000
```

## 5. Repository implementation

The repository implements this workflow in R rather than as a single standalone command. The relevant scripts are:

- [bin/D0_H3K27me3_genes_classification.R](../bin/D0_H3K27me3_genes_classification.R)
- [bin/D4_H3K27me3_genes_classification.R](../bin/D4_H3K27me3_genes_classification.R)

The core workflow in these scripts is:

1. Load the TSS-linked H3K27me3 table.
2. Ensure that each gene is represented once by a single TSS-associated record.
3. Create a gene-level table with columns such as gene, chromosome, TSS position, peak start, peak end, and domain length.
4. Apply the 6000 bp cutoff to define broad versus narrow classes.
5. Label genes with no overlapping domain as negative.
6. Optionally compare the resulting groups with differentially expressed genes using a hypergeometric test.

A typical execution with Docker looks like this:

```bash
docker run --rm -v "$PWD:/work" -w /work rocker/tidyverse:4.5.1 Rscript bin/D0_H3K27me3_genes_classification.R
```

And for the day-4 analysis variant:

```bash
docker run --rm -v "$PWD:/work" -w /work rocker/tidyverse:4.5.1 Rscript bin/D4_H3K27me3_genes_classification.R
```

The paths inside the scripts are project-specific, so they may need to be adjusted to match the local directory structure before execution.

## 6. Outputs generated by the workflow

The analysis usually produces:

- a gene-level classification table with one row per gene
- plots of the domain-width distribution across genes
- sets of broad, narrow, and negative genes that can be used in downstream analyses
- optional statistics comparing the classified gene sets with DEGs or other gene categories

In the notebook workflow, these gene sets are then used for downstream visualization, heatmaps, and comparative analyses.

## 7. Notes and practical recommendations

- Use the same genome build and TSS definition across all samples and comparisons.
- Keep the 6000 bp threshold fixed when comparing multiple conditions or time points.
- Store the final classification table as a tab-separated file for reuse in later steps.
- If different peak-calling strategies are used, confirm that the merged-domain definition remains consistent with the one used in the notebook and scripts.

## 8. Relationship to the other interval-based scripts in this repository

The repository also contains [bin/peaks_classification.sh](../bin/peaks_classification.sh), which performs interval-based operations with bedtools. That script is useful for general genomic interval partitioning and overlap workflows. The H3K27me3 TSS-domain classification described here follows the same general principle of assigning genomic features to classes, but the actual promoter-focused implementation in this project is the R-based workflow above.
